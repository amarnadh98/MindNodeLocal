## Unreleased
### Added (M2, in progress)
- Per-node styles, shapes and the Inspector (slice 3, F-STY-1/2/3/6/7/8, ADR-0011, formatVersion 3): `Theme.applyingOverrides(_:to:variant:)` now folds a node's stored `NodeStylePatch` into its theme-resolved style — every field (shape; fill hex/none; border color/width/dash; corner radius; padding; shadow none/soft/raised per §7.2; font name/size/weight; text color/alignment; min/max width), unknown values ignored per field, and the `BuildCaches` fast path untouched: nodes without overrides pay one nil-check (measured on the 5k release fixture: keystroke 12.8 → 12.9 ms, within noise and the ≤5% guard; the 12 ms absolute guard was already failing on this hardware at baseline). Measured sizes honor overrides (fonts/padding/widths change the frame; `minWidth` floors auto-width), and per-node **branch** overrides (color/width/taper/line style) act on the connector drawn from the node's parent to it — ADR-0011 — with `SceneBranch.lineStyle` (curved/tapered/straight/elbow/none) now driving both the layer tree and the export renderer. The cloud shape is a real six-bump arc outline (not the old ellipse placeholder), dashed borders stroke §7.2's 4/3 pattern, and title alignment (left/center/right) pins the text block to its content edge. New undoable commands with exact inverses, covered by the property-test fuzz: `setStyle(ids:patch:)` (merge — one step over any selection), `resetStyle(ids:keys:)` ("Reset to theme", per-key or whole patch), `setAppearance(mode:)` (F-STY-6, persisted in `map.json`'s existing `appearance` field) and the theme trio `setThemeSelection`/`setTheme`/`setThemeOverrides` — the latter two's inverses route through a full-selection snapshot, fixing a latent `setTheme` undo bug that dropped stored overrides when clearing a selection. The Inspector (right pane, `NSSplitViewItem` inspector style, hidden by default, ⌥⌘I / View ▸ Toggle Inspector, visibility persisted): SwiftUI-hosted tabs — **Style** (context-aware Node/Text/Branch sections + Connection/Boundary placeholders; overridden properties show a dot + per-row "Reset to theme"; mixed multi-selection values shown as such; color pickers offer the theme palette first, then recent colors, then the system panel, F-STY-7), **Theme** (grid of the 12 built-ins with live hover preview — a view-only temporary theme that never dirties the document — click applies via `setTheme` as one undo step; the Rainbow toggle persists via the new `ThemePatch.rainbowBranches` override; Recolor Branches; per-document Appearance Auto/Light/Dark) and **Layout** (placeholder for the layout slice). New documents open with the user's default-theme preference (`UserDefaults`, Inspector ▸ Theme ▸ New Documents). formatVersion 3 adds three optional fields (`NodeStylePatch.fontWeight`, `NodeStylePatch.minWidth`, `ThemePatch.rainbowBranches`) with the v2→v3 migration stamping the version only (nothing to back-fill; fixture-tested for both steps). Tests: MapCore style/theme commands + migrations, MapRender override resolution per field + shape anchor geometry + raster ink-coverage goldens per shape + cloud topography + dash/alignment raster, CanvasKit scene-level override resolution + branch-override semantics + rainbow override, and 9 hosted app tests (⌥⌘I toggling, inspector fill change = one undo step rendered on canvas, multi-selection one step, reset-to-theme, theme apply = one step + recolor, hover preview never dirty, rainbow/recolor through the store, appearance override, default theme for new documents).
- Theme engine (slice 1, F-STY-3/4/8, ADR-0009): `MapRender.Theme` — a pure `Codable`/`Sendable` theme value (id, name, light + dark schemes with canvas color, 8–12 palette colors and root/1/2/3+ level styles; branch line style & widths; rainbow-branches toggle; connection & boundary style placeholders) whose `Codable` schema *is* the `.arbortheme` JSON contract (friendly encodings: `"none"`, `"#RRGGBB"`, `{"palette": 0.16}`); `Theme.resolvedStyle(level:level1Index:variant:)` implements F-STY-3 resolution — theme → level style → branch color from the level-1 ancestor's palette index — with a documented seam for per-node overrides (inspector slice). Twelve built-in themes (Paper, Graphite, Pastel, Ocean, Forest, Sunset, Mono Ink, Chalkboard, Neon, Blueprint, Sakura, Study) as Swift literals, all dynamic, palettes chosen and fixture-tested for WCAG AA (≥ 4.5:1 text-vs-fill in both variants, every palette entry for tinted fills); Paper is the first data theme and `PaperThemeEquivalenceTests` prove it resolves pixel-identically to the reference (levels 0–4 × indices 0–15 × both variants, every field), existing MapRender tests untouched and green. `SceneGeometry` resolves styles, canvas color and branch widths from `model.theme?.id` (default paper) at the appearance variant.
- Persistent branch palette index (ADR-0004 follow-up, formatVersion 2): level-1 nodes store `Node.paletteIndex`, so reordering, moving or deleting level-1 siblings no longer recolors branches; v1→v2 migration back-fills today's positional index (fixture-tested for both versions under `MapCore` tests), new level-1 nodes take the next unused index via the creation commands themselves, and `nil` falls back to position. New undoable commands with exact inverses (covered by the property-test fuzz): `recolorBranches` (F-STY-8's action, a sibling rotation helper + explicit assignments) and `setTheme(id:)` (F-STY-4, preserving stored overrides, `nil` = default). ADR-0004 superseded; ADR-0009 records the model.

### Fixed (M1 slice 8)
- Phantom bold run on root titles: committing a title typed into a semibold-styled node (the Paper theme's root) recorded a `bold` run, because `NodeTitleText`'s extraction treated AppKit's bold font mask as an explicit override — and semibold system fonts carry that mask. A plain-typed root therefore persisted `bold: true` into `map.json` (would export as `**bold**` Markdown/OPML and read as a style override). Bold is now extracted relative to the node's base font (weight comparison), so the theme's semibold is not an override, while ⌘B on a semibold base still records. Two regression tests in `NodeTextEditorTests`, plus the golden scenario's no-phantom-run assertion.

### Fixed (review on PR #3)
- Multi-id delete undo: anchors are deduplicated (an id listed twice restored twice) and sorted by `(parent, slot)` so selection order no longer corrupts sibling order; ids covered by an ancestor in the same selection restore inside the ancestor's snapshot instead of double-inserting.
- `group` applies are all-or-nothing (working copy, assign on success), so a failed compound command can't leave a half-applied, un-undoable change.
