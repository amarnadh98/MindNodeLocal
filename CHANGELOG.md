## Unreleased
### Added
- Product & technical specification (SPEC.md), research notes, ADR-0001.
- M0 foundation: 9 SPM packages under `Packages/` (Swift 6 strict concurrency, macOS 26 minimum).

### Added (M2, in progress)
- Theme engine (slice 1, F-STY-3/4/8, ADR-0009): `MapRender.Theme` — a pure `Codable`/`Sendable` theme value (id, name, light + dark schemes with canvas color, 8–12 palette colors and root/1/2/3+ level styles; branch line style & widths; rainbow-branches toggle; connection & boundary style placeholders) whose `Codable` schema *is* the `.arbortheme` JSON contract (friendly encodings: `"none"`, `"#RRGGBB"`, `{"palette": 0.16}`); `Theme.resolvedStyle(level:level1Index:variant:)` implements F-STY-3 resolution — theme → level style → branch color from the level-1 ancestor's palette index — with a documented seam for per-node overrides (inspector slice). Twelve built-in themes (Paper, Graphite, Pastel, Ocean, Forest, Sunset, Mono Ink, Chalkboard, Neon, Blueprint, Sakura, Study) as Swift literals, all dynamic, palettes chosen and fixture-tested for WCAG AA (≥ 4.5:1 text-vs-fill in both variants, every palette entry for tinted fills); Paper is the first data theme and `PaperThemeEquivalenceTests` prove it resolves pixel-identically to the reference (levels 0–4 × indices 0–15 × both variants, every field), existing MapRender tests untouched and green. `SceneGeometry` resolves styles, canvas color and branch widths from `model.theme?.id` (default paper) at the appearance variant.
- Persistent branch palette index (ADR-0004 follow-up, formatVersion 2): level-1 nodes store `Node.paletteIndex`, so reordering, moving or deleting level-1 siblings no longer recolors branches; v1→v2 migration back-fills today's positional index (fixture-tested for both versions under `MapCore` tests), new level-1 nodes take the next unused index via the creation commands themselves, and `nil` falls back to position. New undoable commands with exact inverses (covered by the property-test fuzz): `recolorBranches` (F-STY-8's action, a sibling rotation helper + explicit assignments) and `setTheme(id:)` (F-STY-4, preserving stored overrides, `nil` = default). ADR-0004 superseded; ADR-0009 records the model.
- Minimap (F-CAN-6, slice 2): `MinimapView` — a CanvasKit overlay anchored bottom-right of the canvas showing a simplified scene (node rects in their branch colours, no text) plus the live viewport rect. Geometry is pure and headless (`MinimapProjection.fit` letterboxes the scene into the minimap; `MinimapGeometry` maps a clicked minimap point to the camera that centres it, and answers F-CAN-6's auto-hide predicate: hidden when the whole map already fits the viewport, an empty scene/viewport counts as fitting, a 1 pt tolerance keeps a just-fitted view from strobing). Drawing stays cheap per the task: the simplified scene rasterizes into a cached `NSImage` that is re-rendered only on scene/size/appearance changes — camera moves only blit the cache and re-stroke the viewport rect (a rebuild-count seam proves it in tests). Click or drag pans the canvas by emitting the new camera through `onCameraChange` (the view never touches the canvas); ⌥⌘M (new View ▸ Minimap item, checkmark state) flips the persisted-per-user `ShowsMinimap` UserDefaults preference, effective visibility = preference ∧ auto-hide. Light/dark follows the host's per-variant scene rebuild plus a hairline dynamic border; Reduce Transparency swaps the `NSVisualEffectView` material for a solid window background (workspace-notification driven). VoiceOver: a standalone button-labelled "Minimap" element with a press action that centres the map — a sibling of the canvas's node-row hierarchy, never inside it. 10 headless CanvasKit tests (fit transform, round-trip, viewport mapping, click→camera-centre, auto-hide predicate incl. tolerance/empty cases, view wiring, cached-snapshot policy, VoiceOver press) + a hosted pixel test drawing scene rects and the viewport stroke over the solid fallback background.
- Document-window toolbar (SPEC §4.1/§7.1, slice 2): a customizable `NSToolbar` in the new `DocumentWindowController+Toolbar.swift` — unified-compact style, `allowsUserCustomization`, configuration autosaved per user under the identifier — with items for Add Child, Add Sibling (always creates below, the VoiceOver semantics, bypassing ⏎'s enter-edit rule), Delete, Fold/Unfold, flexible space, Zoom Out, a zoom-% pull-down (F-CAN-2 step list with a checkmark at the current zoom plus Fit), Zoom In, Zoom to Fit, and the Minimap toggle. Every item routes to the EXISTING first-responder actions (`addChildAction:`, `addSiblingBelow:`, `deleteSubtreeAction:`, `toggleFoldAction:`, the canvas's zoom actions); only the zoom steps needed one new selector (`zoomStepAction:` → `canvas.zoomToScale`). Validation by selection via `NSToolbarItemValidation`/`NSMenuItemValidation` on the window controller (nil-target items resolve there through the responder chain): add/delete disable with nothing selected, fold disables without a foldable selection and flips its face (Fold/Unfold, chevron circle) with the target's state, zoom/minimap never need a selection, and the same rules now also disable the corresponding menu items. SF Symbols icons, labels, tooltips with shortcuts. The zoom-% accessory rides the pull-down's face and follows every camera move; the window title keeps the document name (auto-named per F-EDT-14). Pinning the designed content size after the toolbar install (`frameRect(forContentRect:)`) keeps the canvas at its 900×600 area — assigning a toolbar to a made window grows the content view under the camera math. 4 hosted tests: default/allowed identifiers and installed items, validation disabling Delete with no selection (toolbar + menu path, fold-face flip), ⌥⌘M toggling the minimap with the persisted preference, checkmark state and auto-hide interplay, and a minimap pan driving the real canvas camera.

### Added (M3, in progress)

- Connections, boundaries and summaries (F-REL-1/2/3, slice b + F-REL-5's Copy Node Link): the model's `connections`/`boundaries`/`summaries` fields are now backed by fine-grained `MapCommand`s with exact inverses (`addConnection`/`removeConnection`/`editConnection`, `addBoundary`/`removeBoundary`/`editBoundary`, `addSummary`/`removeSummary` — validated apply: dangling endpoints/self-links/bad ranges throw, so the all-or-nothing contract holds; covered by the extended property fuzz, where the remove inverses restore the whole list snapshots so ordering survives undo). ### Fixed (CI)
- The `xcode` job could hang for hours after every test had passed. A test document's timed autosave fired late, failed, and AppKit's modal error alert kept the test host from exiting. ### Fixed (M1 slice 8)
- Phantom bold run on root titles: committing a title typed into a semibold-styled node (the Paper theme's root) recorded a `bold` run, because `NodeTitleText`'s extraction treated AppKit's bold font mask as an explicit override — and semibold system fonts carry that mask. A plain-typed root therefore persisted `bold: true` into `map.json` (would export as `**bold**` Markdown/OPML and read as a style override). Bold is now extracted relative to the node's base font (weight comparison), so the theme's semibold is not an override, while ⌘B on a semibold base still records. Two regression tests in `NodeTextEditorTests`, plus the golden scenario's no-phantom-run assertion.
