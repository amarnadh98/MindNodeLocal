# ADR-0025: Onboarding as code — welcome, tour map, tips, and a menu-walked cheat sheet

Date: 2026-11-19
Status: Accepted
Milestone: M2 (Look & feel)

## Context

F-ONB (SPEC §5.19) asks for a first-launch 3-card welcome whose
"Open Sample Map" is itself the tutorial, a searchable ⌘/ cheat sheet,
designed empty states, and one contextual tip per session. SPEC is
silent on where the sample map lives, how the cheat sheet stays
current, and how tips count a "session". The same slice also owns the
app icon (SPEC §7.7), which SPEC wants as an `.icon` (Icon Composer).

## Decision

### 1. The sample map is built from MapCore models in code

`SampleMap.buildModel()` constructs the tour map (original text, every
branch names a shortcut the app already answers) the way
`TemplateCatalog` builds its templates: no bundled resource to drift
from the schema, `MapValidator`-clean by construction, and a content
change is a code review. "Open Sample Map" writes it fresh to
Application Support (`Arbor Tour.arbor`) and opens it as a real
document — regenerating on every open keeps the tour current with the
app; it is disposable tutorial content, never user data.

### 2. The welcome is a plain NSWindow + hosted SwiftUI

A `WelcomeCoordinator` (owned by AppDelegate) shows once per user
(UserDefaults `OnboardingWelcomeSeen`); any dismissal marks it seen;
Help ▸ "Welcome to Arbor" reopens it regardless. The window is
`isReleasedWhenClosed = false` — programmatic windows default to
release-on-close, which over-releases under a coordinator-owned
lifetime (this bit the hosted tests first).

### 3. Tips are a session-scoped claim plus per-tip dismissal

`TipCenter` owns the two rules: at most one tip per *launch*
(static claim) and per-tip "Got it" keys (`TipDismissed.<id>`) that
live forever. Triggers live with the host moments (fresh-document
showWindow, a finished drag-reparent, a map crossing the fold
threshold). Settings ▸ Advanced ▸ Reset tips (SPEC §5.20's row) clears
the keys — the store this slice adds.

### 4. The cheat sheet walks NSApp.mainMenu; canvas keys are curated

The ⌘/ sheet's menu section is generated by walking the live
`NSApp.mainMenu` (leaf items with key equivalents, enabled or not — a
reference list, not a command list), the same never-drifts source the
⇧⌘P palette uses. The SPEC §6 keys that are *deliberately* keyDown-only
(arrow navigation, drag modifiers, presenting/recall/study hold-keys)
can never appear in menus, so they ride a curated static list that
names only what is actually implemented — Space-drag-as-connection is
absent until F-REL-1 lands.

### 5. The app icon is drawn by a committed script

`scripts/generate_app_icon.swift` (plain `swift` invocation,
CoreGraphics + ImageIO only) draws the original glyph — a forking
branch with node tips, one amber, on the brand-teal gradient — and
writes every macOS AppIcon size plus Contents.json into the asset
catalog; the PNGs are committed so builds need no extra tooling.
SPEC's `.icon` (Icon Composer, layered light/dark/tinted) stays the
noted follow-up for the ship milestone; the PNG appiconset is the
accepted v1 form.

Also fixed here: the project's `resources:` key was dead config
(XcodeGen ignores it — App/Resources never produced a resources build
phase); the icon's asset catalog is wired as a `sources:` entry with
`buildPhase: resources`, the supported spelling.

## Consequences

- Tour content changes ship as code (reviewable), and the welcome's
  "seen" flag survives reinstalls only if UserDefaults does.
- The cheat sheet's canvas tables are hand-truthed per milestone;
  a new hold-key needs one curated line, reviewed against what ships.
