# ADR-0016: Library index on the system SQLite3 C library, and templates built in code

Date: 2026-11-19
Status: Accepted

## Context

SPEC §11.1 suggests **GRDB** for the library index (F-LIB-3): a disposable,
fully rebuildable store powering full-text search, backlinks, the Concept
Index and Study-Due aggregation. But AGENTS.md caps runtime dependencies at
eight (each requiring an ADR) and the app already plans to spend that budget
elsewhere. Separately, F-LIB-5 requires twelve built-in templates; the task
allows either bundled `.arbor` resources generated by a script or models
built from `MapCore` in code.

## Decision

1. **`MapLibrary` wraps the system SQLite3 C library directly**
   (`import SQLite3`, ~200 lines of `SQLite3Store` — open, exec, prepared
   statements, transactions) behind the `LibraryDatabase` actor. FTS5 —
   available in Apple's system SQLite on macOS — backs the node text index
   with the default unicode61 tokenizer. **No new runtime dependency.**

2. **Built-in templates are plain `MapModel` values built in code**
   (`TemplateCatalog`), all content original to Arbor. "Save as Template…"
   writes user templates as ordinary `.arbor` packages under
   `Application Support/Arbor/Templates`; "New from Template" materializes
   a copy with fresh docID + node ids, so the template file is never edited.

## Consequences

- The dependency count stays at zero for this milestone; the wrapper is
  small, synchronous and confined to one actor, so all DB access is off the
  main actor and results are `Sendable`.
- The index schema needs no migrations: `formatVersion`-style versioning is
  unnecessary because the store is disposable — delete the file and rebuild
  (the UI exposes "Rebuild Index", and a corrupt store is deleted and
  recreated on open).
- FTS5's unicode61 tokenizer does no word segmentation, so CJK text is one
  token per run: mid-run substring search misses (`計画` inside
  `プロジェクト計画`), while prefix search (`プロジェクト`) hits. Upgrading to the
  trigram tokenizer (needs ≥ 3-char queries) is the documented follow-up if
  CJK substring search matters in practice.
- Node text is indexed pre-folded (NFKC + case + diacritic + width fold via
  `ConceptText`), so search and the Concept Index agree on one normalization
  for every script.
- The canonical deep-link format for Concept Index links is
  `x-arbor://<docID>/<nodeID>` (both UUIDs, case-insensitive). The M8 URL
  scheme handler will resolve these; they are stored in the index's `links`
  table parsed for backlinks (F-LIB-3).
- Study-due aggregation (F-STD-7) is exposed as
  `LibraryDatabase.dueCounts(now:)` — per-map due-today and never-scheduled
  card counts — for the study dashboard agent to consume; the card rule
  mirrors F-STD-1's basic-card policy locally (`LibraryCardPolicy`) so
  `MapLibrary` depends only on `MapCore`.
- Templates in code are deterministic (fixed timestamps), golden-testable,
  and validated by `MapValidator` — but they ship in the binary rather than
  as inspectable files; user-saved templates are real packages, which is
  what the spec's "Templates live in Application Support/Templates" point
  is about.
